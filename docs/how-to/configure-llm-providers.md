# Configure LLM providers

The gateway uses two optional providers. Both are configured in `apps/api/.env`
(or the process environment) and read once at startup by
[`container.py`](../../apps/api/src/shield_api/container.py).

| Provider | Key | Used for |
| --- | --- | --- |
| Groq | `GROQ_API_KEY` | Llama Guard moderation, the Analyst/Warden debate (Layer 2), and the assistant's fallback chat model |
| Google Gemini | `GOOGLE_API_KEY` | The assistant's primary chat model |

## Enable Groq

1. Create an API key in the Groq console.
2. Add it to `apps/api/.env`:

   ```dotenv
   GROQ_API_KEY=gsk_...
   ```

3. Optionally choose models (defaults shown):

   ```dotenv
   GROQ_GUARD_MODEL=llama-guard-3-8b
   GROQ_DEBATE_MODEL=llama-3.3-70b-versatile
   GROQ_CHAT_MODEL=llama-3.3-70b-versatile
   ```

   `GROQ_GUARD_MODEL` must be a Llama Guard-style model that answers `safe` or
   `unsafe` followed by category codes. `GROQ_DEBATE_MODEL` must be able to
   return a JSON object on request.

4. Restart the gateway (`mise run api:dev` reloads on code changes, not on `.env` changes).
5. Check:

   ```bash
   curl -s http://localhost:8000/api/v1/health
   ```

   `moderation_enabled` and `adjudication_enabled` should both be `true`.

## Enable Gemini

1. Create a Gemini API key in Google AI Studio.
2. Add it to `apps/api/.env`:

   ```dotenv
   GOOGLE_API_KEY=...
   GEMINI_MODEL=gemini-2.5-flash
   ```

3. Restart the gateway. Send an allowed prompt through `/chat`; the
   `FINAL_RESPONSE` text is now generated by Gemini instead of the canned reply.

Gemini affects only the assistant's answer. It is not used for screening.

## Assistant model order

The demo assistant tries models in this order and uses the first that answers:

1. Gemini (`GEMINI_MODEL`), if `GOOGLE_API_KEY` is set
2. Groq (`GROQ_CHAT_MODEL`), if `GROQ_API_KEY` is set
3. A canned reply: `AI S.H.I.E.L.D. processed your request.` plus the tools used

Failures are logged as warnings and the next model is tried.

## What degrades without each key

| Configuration | Moderation | Layer 2 | Assistant answer |
| --- | --- | --- | --- |
| Both keys | Llama Guard via Groq | Debate via Groq | Gemini, then Groq |
| `GROQ_API_KEY` only | Llama Guard via Groq | Debate via Groq | Groq |
| `GOOGLE_API_KEY` only | none | conservative fallback | Gemini |
| Neither | none | conservative fallback | canned reply |

Conservative fallback: any prompt that needs Layer 2 gets verdict `UNCERTAIN` and
policy `RESTRICTED` (only `LOW`-risk tools), or `SAFE`/`ALLOW_ALL` if the caller
has `GRANTED` clearance. Nothing is blocked by the fallback; Layer 1 blocks still
apply. See [Verdicts and policies](../reference/verdicts-and-policies.md#layer-2-fallback).

Runtime failures degrade the same way even with keys set:

| Failure | Effect |
| --- | --- |
| Moderation call raises | Treated as not flagged (`fail_closed=False`); the error is recorded in `ModerationResult.error` |
| Any debate call raises | Conservative fallback, keeping the turns completed so far |
| Warden reply is not valid JSON or has unknown enum values | Conservative fallback |

## Use providers from your own code

The engine takes any object implementing the `ChatModel` port. With the
`groq` extra installed:

```python
from shield_engine import DebateAdjudicator, LlamaGuardModerator, Shield
from shield_engine.adapters.groq import GroqChatModel
from shield_engine.models import load_baseline

shield = Shield(
    load_baseline(),
    moderator=LlamaGuardModerator(GroqChatModel(api_key, "llama-guard-3-8b"), fail_closed=True),
    adjudicator=DebateAdjudicator(GroqChatModel(api_key, "llama-3.3-70b-versatile")),
)
```

Set `fail_closed=True` if moderation is a control you rely on: provider errors then
flag the prompt with category `ERROR`, which sends it to Layer 2. The gateway
uses the default, `fail_closed=False`.

To add another provider, write a class with an
`async complete(messages, *, temperature=0.0, max_tokens=None) -> str` method.
[`demo/gemini.py`](../../apps/api/src/shield_api/demo/gemini.py) is a complete example.
