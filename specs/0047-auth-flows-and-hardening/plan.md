# 0047 — Auth flows and hardening: implementation plan

- **Spec:** [spec.md](spec.md)

## Approach

### 1. Auth flow store (`apps/api/src/shield_api/services/auth_flows.py`)

Add an `AuthFlowStore` protocol with two implementations:
- `InMemoryAuthFlowStore` (development and unit tests)
- `RedisAuthFlowStore` (production when `REDIS_URL` is configured, storing JSON under `authflow:<flow_id>` with `EX=ttl_seconds`)

Each `AuthFlowRecord` holds:
- `purpose: Literal["signup", "recovery", "email_change"]`
- `browser_hash: str` (`sha256` hex of the server-minted `HttpOnly` `shield_auth_browser` cookie, never the raw cookie)
- `code_verifier: str | None` (captured from the throwaway Supabase client's PKCE storage before discarding the client)

TTLs: 3600s (1 hour) for `signup` and `email_change`; 1800s (30 minutes) for `recovery`.

### 2. Identity provider (`apps/api/src/shield_api/services/identity.py`)

Extend `PlayerIdentity` and `SupabasePlayerIdentity`:
- Accept an optional `redirect_to` override on `register`, `resend`, `recover`, and `request_email_change` so the router can append `?flow=<flow_id>` (and `&intent=email_change`).
- Capture the PKCE `code_verifier` generated by the throwaway client on `sign_up` and `reset_password_for_email` and return it alongside the result.
- Add `verify_confirmation(*, code, code_verifier, token_hash, token_type) -> VerifiedPlayer` (calling `verify_otp` for `token_hash` or `exchange_code_for_session` for `code` + `code_verifier`, then signing out the Supabase session).
- Add `complete_password_reset(*, code, code_verifier, token_hash, new_password) -> str` (verifies recovery token/code, updates password via Supabase, signs out Supabase session, and returns the user's email).
- In `_register`, catch only existing-account errors (`user_already_exists`, `email_exists`) as `None` (`202`); raise `IdentityUnavailableError` on 5xx, timeouts, or network errors.

### 3. Auth, Account, and Clearance routers (`apps/api/src/shield_api/routers/`)

- `routers/auth.py`:
  - Add helper `_ensure_browser_cookie(request, response, settings, ttl)` that reuses a valid `shield_auth_browser` cookie or mints a 256-bit `HttpOnly; Secure; SameSite=Lax; Path=<API_PREFIX>` cookie, returning `sha256(token)`.
  - Add `POST /auth/confirm` (`PlayerConfirmRequest` → `PlayerConfirmResponse`) implementing the same-browser auto-sign-in (and clearing `shield_auth_browser`) vs different-browser `confirmation_required` / `confirmed` state machine.
  - Add `POST /auth/reset-password` (`PlayerResetPasswordRequest` → `PlayerResetPasswordResponse`) verifying the recovery token, updating the password, revoking all gateway sessions (`players.revoke_sessions(email, keep=None)`), and purging trained models.
  - Map `IdentityUnavailableError` on `POST /auth/register` to `503`.
  - Remove `rate_limiter.record_failure("login_fail", ...)` from the `EmailNotConfirmedError` branch.
- `routers/account.py` and `routers/clearance.py`:
  - Replace in-memory-only `container.attempts` with a Redis-backed attempt limiter when `REDIS_URL` is configured.
  - Add production rate limit (`5 / 15 minutes` per email) on `POST /auth/account/email`.
- `main.py`:
  - Add `Cache-Control: no-store` header on all `/api/v1/auth/*` and `/api/v1/clearance` responses.
  - Add `/auth/recover`, `/auth/resend-confirmation`, `/auth/confirm`, and `/auth/reset-password` to `botid_paths`.
- `services/players.py`:
  - In `SupabasePlayerStore._insert_session`, prune expired rows (`lte("expires_at", now.isoformat())`) before insert.
- `container.py`:
  - Validate `WEB_BASE_URL` in `build_container` when `APP_ENV == "production"` (non-blank, non-localhost `http(s)` origin), and strip trailing slashes.

### 4. Web client (`apps/web/`)

- `nuxt.config.ts`: add `routeRules: { '/auth/**': { headers: { 'Referrer-Policy': 'no-referrer', 'Cache-Control': 'no-store' } } }`.
- `shared/utils/apiProxy.ts`: reject state-changing requests (`POST`, `PUT`, `PATCH`, `DELETE`) with `403 {"detail": "Cross-site request blocked."}` when `sec-fetch-site === 'cross-site'` or when `origin` is present and differs from the request URL's origin.
- `shared/utils/botid.ts`: add the four new `POST` routes to `BOTID_PROTECTED_ROUTES`.
- `app/plugins/botid.client.ts`: switch to object syntax with `enforce: 'pre'`.
- `app/utils/playerAuth.ts`:
  - Add `recoverSchema` and `resetPasswordSchema` (using `strongPasswordSchema`).
  - Update `loginFailure(statusCode, detail)` so only the unconfirmed-email `403` detail returns `'unconfirmed'`.
- `app/composables/usePlayerAuth.ts`:
  - Remove `.trim()` from passwords in `signInWithPassword` and `registerAccount`.
  - Add `confirmEmail` and `resetPassword` helpers.
- `app/pages/auth/confirmed.vue`:
  - Read query params on mount, immediately call `router.replace({ path: '/auth/confirmed', query: {} })`, and render loading / `signed_in` / `confirmation_required` (with **Confirm email** button) / `confirmed` / error states.
- `app/pages/auth/reset-password.vue` (new):
  - Read query params on mount, clear URL via `router.replace`, render `PasswordStrengthField` form, call `POST /auth/reset-password`, and navigate to `/auth/login`.
- `app/pages/auth/recover.vue`: wire `:schema="recoverSchema"`.
- `app/pages/settings.vue`: update email-change confirmation toast to mention both inboxes.
- `app/app.vue` & `app/layouts/dashboard.vue`: move `onMounted(loadAccess)` from `app.vue` to `dashboard.vue`.

## Alternatives considered

| Option | Why not |
| --- | --- |
| JS-created (`document.cookie`) `shield_auth_browser` | Cannot be `HttpOnly`; XSS could read or forge it (violates OWASP ASVS V3.4.2). Server-minted `HttpOnly` achieves the exact same flow with stronger security. |
| Move Supabase Auth SDK into the browser | Violates the gateway security boundary ("Credentials stop at the gateway"; browser must never hold Supabase tokens). |
| Auto-confirm on `GET /auth/confirmed` SSR | Email scanners (Outlook Safe Links) pre-fetch `GET` URLs and would consume one-time links before the human clicks (violates RFC 9110 §9.2.1). |
| Auto-sign-in without checking the browser cookie | Opening a forwarded or scanned link on another device would grant a live session without a password. |

## Risks and rollback

- **Risk:** Production Vercel deployment missing `WEB_BASE_URL` will fail cold start after `API-AUTH-014`. Mitigation: set `WEB_BASE_URL=https://ai-shield-delta.vercel.app` on the `apps/api` Vercel project and add `https://ai-shield-delta.vercel.app/auth/confirmed` and `https://ai-shield-delta.vercel.app/auth/reset-password` to Supabase **Redirect URLs** before deploying.
- **Risk:** Existing `API-VERIFY-001`, `API-VERIFY-002`, and `WEB-VERIFY-003` tests expect no `Set-Cookie` on register, masked outages, and a static `/auth/confirmed` page. Mitigation: update those tests explicitly when spec 0047 is accepted.
- **Rollback:** Revert the commit; no database migration is required.
